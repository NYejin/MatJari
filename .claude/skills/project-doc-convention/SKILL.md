# 프로젝트 산출물 컨벤션

## 폴더 구조 (고정, 임의로 이름/번호를 바꾸지 않는다)

저장소 루트 기준:
```
MatJari/        ← 소스코드 (backend / frontend / seatmap-service). 번호 없음.
산출물/           ← 아래 00, 02~09 번호 폴더. 01은 결번(소스코드는 MatJari/에 따로 있으므로).
```

| 번호 | 폴더 (산출물/ 하위) | 형식 | 채워지는 시점 |
|---|---|---|---|
| 00 | 완료보고서 | PPT/PDF | 프로젝트 종료 시 |
| — | (01 결번 — 소스코드는 저장소 루트의 MatJari/ 참고) | | |
| 02 | 시연영상 | mp4 등 | 핵심 기능 완성 후 |
| 03 | 프로젝트계획서 | docx | 기획 단계 (완료) |
| 04 | 요구사항정의서 | docx/xlsx | 기획 단계, 기능 추가 시 갱신 |
| 05 | WBS | xlsx | 기획 단계, 일정 변경 시 갱신 |
| 06 | 다이어그램(시퀀스/아키텍처) | png/dot | API 흐름 확정 시 |
| 07 | 작업일지 | md | 매 작업 세션마다 |
| 08 | ERD | png (graphviz .dot 소스 포함) | 스키마 변경 시 갱신 |
| 09 | 배포URL | md | 배포 완료 시 |

## 문서 스타일 (docx)
- 표 헤더: 배경 `#4472C4`, 글자색 흰색, 굵게
- 본문 폰트: 맑은 고딕
- A4 (11906 x 16838 DXA)
- 표는 `columnWidths`와 셀 `width`를 DXA 단위로 동일하게 맞춘다

## 문서 스타일 (xlsx, WBS/요구사항정의서)
- 헤더 행: 파란 배경(#4472C4) + 흰 글자
- 기간 컬럼은 하드코딩 금지, `=(종료일-시작일)+1` 수식 사용
- 작성 후 반드시 `recalc.py`로 수식 오류 검증
- 요구사항정의서는 팀 프로젝트 때 쓰던 양식(구분/서비스/기능명/기능설명/개발상태/개발우선순위/담당자/선행기능/비고, 구분·서비스 셀 병합)을 따른다

## 작업일지 규칙
- `## YYYY-MM-DD` 헤더 아래 그날 결정사항/구현내용을 불릿으로 기록
- "결정"과 "구현"을 구분해서 적는다 (예: "~로 결정" vs "~구현 완료")

## 파일 전달 규칙
- **소스코드**(MatJari/ 하위 수정분) → `MMDD-순번_수정내역영문.zip`로 압축해서 전달
  (예: 1002-1_add-tech-stack-rationale). 순번은 그날 몇 번째 수정인지.
- **문서**(산출물/ 하위 계획서·요구사항정의서 등) → 압축 없이 단일 파일 그대로 전달

## 문서 갱신 트리거
- 새 기능/엔드포인트 추가 → 산출물/04(FR/UC 번호 추가), 산출물/05(일정 반영)
- 스키마 변경 → 산출물/08 갱신
- API 흐름 확정 → 산출물/06 작성
- 매 세션 종료 → 산출물/07 갱신
