## 검증된 접근 (실제 멜론티켓 개별좌석도 이미지로 테스트 완료)

- 딥러닝 불필요. **색상 임계값 또는 배경-제외 방식 + `cv2.connectedComponentsWithStats`** 조합으로 충분.
- 실측 결과: 약 207~210개 좌석 블록, 평균 크기 약 18x18px, 오탐(노이즈) 거의 없음.
- 색상별 상태(판매/예약가능) 매핑은 **하지 않는다**. 이 서비스는 이미 판매 완료된 좌석의
  배치만 재현하면 되므로, "사각형이 어디 있는가"만 중요하다.

## 참조 코드 패턴 (과거 구현, 현재는 태그에만 있음 — 최초 방식이며 이후 아래 '보강'으로 상대 크기 필터·배경색 추정 등이 추가됨)

```python
import cv2

img = cv2.imread(path)
bg_mask = cv2.inRange(img, (240,240,240), (255,255,255))  # 흰색 배경 제외
fg_mask = cv2.bitwise_not(bg_mask)
num_labels, labels, stats, centroids = cv2.connectedComponentsWithStats(fg_mask, connectivity=8)

seats = []
for i in range(1, num_labels):
    x, y, w, h, area = stats[i]
    if 10 < w < 30 and 10 < h < 30 and area > 20:   # 좌석 크기 필터
        seats.append((x, y, w, h, centroids[i]))
```

## 행/열 매핑

1. y좌표 기준 정렬 후, 인접 블록 간 y차이가 임계값(예: 10px) 이내면 같은 행으로 클러스터링
2. 행 옆 숫자 라벨은 Tesseract OCR로 인식 (`pytesseract.image_to_string`, 숫자만 나오도록 `config='--psm 7 digits'` 권장)
3. 같은 행 내에서 x좌표 오름차순 정렬 → 순번 부여
4. x간격이 평균 간격의 1.5배 이상 벌어지면 "통로"로 간주해 번호 스킵 여부를 관리자/사용자 보정 대상으로 표시

## 구현 시 추가된 보강 (2026-10-07, 합성 이미지 48종 검증: 검출 100%, 행·열 100%, 행 OCR 직접 판독 99.6%)

- 검출 전 3x3 opening: JPEG 링잉으로 이웃 블록이 얇게 이어져 합쳐지는 문제 해결 (적용 전 JPEG 합성 이미지에서 208개 중 184개만 검출)
- 배경색은 이미지 가장자리 최빈색으로 추정(절반 미만이면 흰색 폴백, 허용 오차 15). 흰색 계열이면 기존 240~255 제외와 같다
- 좌석 크기는 절대값(10~30px)이 아니라 상대 필터: 후보(6~120px, 채움 비율 0.4 이상) 중 **가장 흔한 크기 군집**(같은 크기 8개 이상)을
  기준으로 w/h 0.75~1.35배만 인정. 40px·12px 좌석도 검출되고, 붙어버린 두 자리 숫자·범례 등은 제외되며 제외 수는 응답
  `stats.discardedComponents`와 `BLOCKS_DISCARDED` 경고로 노출
- 입력 방어: 해상도 12MP/변 8000px(디코딩 전 직접 파서 + Pillow 헤더 이중 검사, OPENCV_IO_MAX_IMAGE_PIXELS), 16비트는 8비트로,
  알파는 흰 배경에 합성, 연결요소 20만/블록 6000/행 300 상한, OCR 호출 3초·전체 30초 예산
- OCR 신뢰도 60 미만, `0`/`000`/앞자리 0, 4자리 이상은 못 읽은 것으로 보고 보간/순번 폴백. 읽힌 행 번호가 나머지의 증가/감소 규칙과
  어긋나면 값은 유지하고 `ROW_LABEL_OUTLIER` 경고만 낸다(번호가 건너뛰는 공연장이 실제로 있어 자동 교정하지 않음)
- 행 클러스터링 기준은 고정 10px이 아니라 블록 높이 중앙값의 0.5배
- 행 번호 OCR: 행 왼쪽 라벨 영역(없으면 오른쪽)을 3배 확대·Otsu 이진화·`--psm 7` + 숫자 화이트리스트. 못 읽은 행은
  읽힌 행의 증가/감소 방향으로 보간(`inferred`), 그래도 안 되면 순번(`sequence`)이고 경고를 낸다
- 통로: 이웃 간격이 행 중앙값 간격의 1.5배 이상이면 통로로 보고하며, `aisleMode`로 번호를 이어서 부여(continue, 기본)할지
  빈 좌석 수만큼 건너뛸지(skip) 선택한다. 통로 정보는 항상 응답에 포함
- 한계: 곡선 배치(호 모양 행)와 좌석 크기가 구역별로 크게 다른 지도는 행 묶기/이상치 필터가 맞지 않을 수 있음.
  실제 멜론 개별좌석도로는 이번에 재검증하지 못했다 (공개 상품 페이지에 좌석맵이 없음 — 이미지 확보는 업로드/이미지 주소 경로)

## 실제 좌석표 대응 (2026-10-07, PR #18로 병합되었다가 현재는 태그에 보관, 사용자가 올린 3개 층 449x549 이미지로 시험)

- 결과: 개선 전 좌석 1619·구역 구분 없이 열 1~39·열 OCR 0 → 개선 후 좌석 1674(붙은 색 좌석 덩어리 14개에서 55석 복원)·구역(층) 3개(1F 23열 974석, 2F 10열 430석, 3F 6열 270석)·열 라벨 OCR 33/39(나머지는 구역 규칙 보간)·버려진 요소 5(무대 글자·층 배지). pytest 199건, 합성 48종 100% 유지
- 원인: ①색 좌석 사이 1px 안티앨리어싱 틈이 위치마다 값이 달라 좌석이 하나의 연결요소로 붙어 크기 필터에서 버려짐 ②층 구분 없음 ③열 라벨이 블록 사이 통로에 있고 작고 연한 회색
- 색 매핑은 하지 않는다. 색상·판매상태를 해석하지 않고 **배경 대비 농도만** 쓴다
- 붙은 덩어리: 붙은 덩어리는 몸통을 분리하고 격자로 분할해 좌석을 복원한다
- 구역 분할: 행 간격이 (기준 간격의) 4배 이상이면 구역을 나눈다. 2.5~4배는 열 라벨이 다시 시작될 때만 나누며 불확실하면 경고 `SECTION_SPLIT_UNCERTAIN`. 응답에 좌석별 `section`과 `sections`를 추가(하위 호환)
- 열/번 체계: 한국 좌석 체계로 '열'(앞에서부터 1열, 뒤로 갈수록 커짐)과 '번'(한 열 안에서 왼쪽→오른쪽 1번, 2번…). 데이터 필드명은 row/col 유지, 열 번호는 **구역별로 재시작**한다
- 통로 라벨: 블록 사이 통로의 라벨을 OCR로 읽고, 구역 안에서 1,2,3 증가 규칙과 **표결**해 값을 정한다(못 읽은 열은 규칙 보간)
- **한계**: 정답 없이 눈·격자 규칙으로 추정했고 임계값은 이미지 1장 기준이다. 열 라벨 6/39 미판독(보간), 사다리꼴 블록의 1번 위치 불명(사용자 정정 대상), 층 이름(1F/2F/3F) 미인식(구역은 위에서부터 1,2,3), 같은 색 좌석 위주 이미지·회색 좌석 8개 미만이면 실패, 이미지 안 글자(무대 표시)가 좌석으로 잡힐 수 있음(합성 시험에서 'STAGE' 글자로 244개 검출)

## 오류 보정 규칙 (변경 금지)

- `SeatCorrection` 레코드로 신고 접수
- **동일한 (좌표, 정정값) 조합이 2건 이상**이면 자동으로 `SeatMapLayout`에 반영
- 1건이면 `status = pending`으로 두고 관리자 확인 대기

> 위 `SeatCorrection`·`SeatMapLayout`은 삭제된 코드를 가리킨다(태그 보관). 정정 신고를 다시 설계할 때 같은 규칙(동일 정정 2건 이상 자동 반영)을 적용한다.

## 서비스 분리

이 로직은 `MatJari/backend`(Spring Boot) 메인 서버가 아니라 `MatJari/seatmap-service`
(별도 FastAPI 프로세스, 현재 폴더 없음 — 태그에서 복구)에 둔다. Spring Boot는 결과 좌표 JSON을 REST로 받아 저장하는
클라이언트 역할만 한다.
