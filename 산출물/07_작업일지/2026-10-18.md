## AI 회차·구역 읽기 (브랜치 `feature/ai-extract-backend`, V21)
### 결정
- 공연 등록 때만 사용, 한 공연당 AI 호출 한 번(같은 링크는 24시간 캐시), 사용자가 확인·수정한 뒤에만 등록. 등록 흐름은 AI가 실패해도 막히지 않는다.
- 모델은 `claude-haiku-5-5`(설정으로 변경), 무료 티어는 쓰지 않는다(입력 학습·사람 검토, 서비스 약관 해석 위험). Max 구독과 API는 결제가 따로이고 구독 로그인을 서비스 백엔드에 쓰는 것은 약관상 금지다.
- 구역은 이름 목록 + 모양(다각형 조각 배열)을 저장하고 같은 이름은 한 구역으로 합친다. 서버는 목록 밖 구역도 거절하지 않는다(드롭다운은 입력 보조). 구역 목록 수정과 이미 등록된 공연의 구역 채우기는 후속.
- 호출 상한: 사용자당 하루 5회, 전체 하루 40회, 동시 2개(메모리 기반).
### 구현
- DB: `performance_zone`, `performance.seatmap_aspect`(V21).
- 입력부: 멜론 상세 이미지 내려받기(허용 호스트·크기·IP 검사), 겹침 슬라이싱, 본문 회차 시각 규칙 파서.
- AI 호출(공식 Anthropic Java SDK 2.34.0): 1차(모든 조각 → 회차·구역 이름·좌석표 위치), 위치 찾기(좌석표 구간을 450px 띠로 나눠 띠 번호 범위를 받음, 좌표를 묻는 방식은 이미지 일부만 차지할 때 기준이 흔들려 폐기), 2차(좌석표만 잘라 구역 모양, 생각 단계 끔·effort LOW), 서버 재검증과 모양 품질 검사(실패 시 1회 재시도, 그래도 미달이면 모양은 버리고 이름만).
- API: `POST /api/performances/ai-extract`, `GET /api/performances/{id}/zones`, 공연 등록 요청의 `zones`·`seatmapAspect`.
- 화면: 링크 확인 직후 자동 읽기(버튼 없음, 진행 중에도 직접 입력 가능), 구역 확인 목록과 모양 미리보기(확대·축소 버튼, 핀치·드래그, Ctrl+휠, 더블탭), 티켓 등록·교환 조건 구역 드롭다운, 약관 제5조의2·방침 7의2.
### 시험
- 실제 멜론 페이지 3건(213943 포함)과 저장해 둔 상세 이미지로 시험. 213943: 회차 3개(본문 규칙, 실제 문구와 일치)·구역 38개(1~7, 9~15, 24~43, E·I·K·P) 읽음. 구역 모양은 윤곽에 대체로 맞으나 호출마다 편차가 있다. 소요 약 13~20초(호출 한 번 기준, 조절 전에는 최대 44초).
- 백엔드 전체 테스트 통과(MySQL IT는 CI에서 실행), 프런트 tsc·빌드 통과. Edge 자동화로 로그인→링크 입력→자동 읽기→구역 확인·확대→3단계→등록(공연 5)→티켓 등록 구역 드롭다운 흐름 확인.
- 이 PC에서 windows-mcp를 `claude mcp add`로 등록해 연결 확인(`uvx windows-mcp serve`), 이 세션에서는 도구가 잡히지 않아 Playwright(Edge)로 대체했다.
### 한계·후속
- 멜론 상세 이미지만 읽는다(YES24는 상세 영역이 Ajax, 티켓링크는 이미지 주소를 얻을 수 없음). 복잡한 지도에서 모양 정확도 편차, 실제 터치 기기 제스처는 미확인.
- 후속: 정확도 평가 세트와 튜닝, 구역 모양 클릭 선택 화면, YES24, 관리자 구역 수정·이미 등록된 공연의 구역 채우기, 관리자 권한 확장(공연 내리기·직접 수정·이용자 관리, 기록만).
- 법·약관 조사는 공식 문서 기준 사실 조사이며 법률 자문이 아니다. 약관·방침의 AI 문구는 법률 검토 전이다.
