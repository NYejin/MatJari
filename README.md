# 맞자리 (MatJari)

같은 공연 티켓을 가진 사람끼리 **좌석을 맞바꾸는** 웹 서비스입니다. 등급 차이가 있으면 추가금을 주고받는 조건으로도 교환할 수 있습니다. 개인 포트폴리오 프로젝트입니다.

재판매(스캘핑)가 아니라 **이미 유효한 티켓을 가진 사람끼리 자리를 옮기는 것**이 목적입니다. 결제는 중개하지 않습니다.

## 어떻게 쓰나

1. **티켓 등록**: 공연을 찾아 내 좌석(회차·구역·열·번)을 등록합니다. 찾는 공연이 없으면 티켓팅 링크를 붙여 넣고 공연과 함께 등록합니다.
2. **희망 조건**: 바꾸고 싶은 회차와 좌석 범위를 고르고, 범위마다 추가금 조건(없음·상관없음·받아야 함·낼 수 있음)을 정합니다.
3. **후보 확인**: 서로의 조건이 맞는 상대(내 좌석이 상대 희망에 있고 상대 좌석이 내 희망에 있음)를 후보로 보여 줍니다. 점수·랭킹·추천은 없고 고르는 것은 사용자입니다.
4. **채팅 → 예약**: 후보에게 제안하면 1:1 채팅이 열립니다. 한쪽이 예약을 제안하고 상대가 수락하면 두 티켓이 잠깁니다.
5. **교환 수락**: 티켓팅 사이트에서 실제 양도를 끝낸 뒤 양쪽이 모두 [교환 수락]을 누르면 교환이 완료되고, 각자 새 자리 티켓과 교환 이력이 남습니다.

## 주요 기능

**교환**
- 자동 후보 조회(같은 공연의 다른 회차끼리도 가능, keyset 조각 조회), 예약 제안·수락·취소, 양쪽 교환 수락
- 매칭별 실시간 채팅(STOMP, 읽음 표시, 종료 후 읽기 전용)
- 알림 6종(헤더 벨, 실시간 푸시)
- 교환 이력, 차단·신고

**공연 등록 도우미**
- 티켓팅 링크에서 제목·공연장·기간·포스터 읽기: YES24·티켓링크·멜론티켓·인터파크(NOL)
- [공연정보 불러오기]로 AI가 상세 페이지에서 **회차**와 **좌석 구역 지도**를 읽어 채웁니다. 결과는 사용자가 확인·수정한 뒤에만 등록됩니다(사용자당 월 3회).
- 티켓·희망 조건 입력 때 구역을 지도에서 클릭해 고릅니다.

**계정**
- 이메일 가입과 소셜 로그인(카카오·구글·네이버), 닉네임 수정, 소셜 계정 연결·해제
- 회원탈퇴(익명화), 개인정보처리방침·이용약관

**관리자**
- 운영 대시보드(핵심 수치, 14일 추이, AI 호출 비용·남은 크레딧 추정)
- 공연 수정 제안 처리, 공연 직접 수정·내리기·삭제, 구역 다시 인식
- 이용자 정지·역할·강제 탈퇴, 신고 처리, 내 티켓 인증 확인, 조치 기록

## AI 회차·구역 읽기는 어떻게 동작하나

직접 학습시킨 딥러닝 모델은 없습니다. **이미 학습된 LLM을 API로 부르는 부분**과 **규칙 기반 영상 처리**를 섞어 씁니다.

| 단계 | 방법 |
|---|---|
| 상세 페이지 받기 | 고정 URL 템플릿으로만 요청합니다(사용자가 준 URL은 직접 요청하지 않음, SSRF 방어). 멜론·인터파크(NOL)는 HTML, 티켓링크는 별도 컨테이너의 Chromium으로 화면을 그려 읽습니다. |
| 회차 | Claude(Haiku 5.5)가 본문 글자와 상세 이미지를 함께 보고 기간·요일별 시각·휴연일 맥락으로 날짜마다 시각을 만듭니다. AI가 못 주면 정규식 규칙을 씁니다. |
| 구역 모양 | 순수 Java 영상 처리(`ShapeSegmenter`): 배경색 판정, 중간값 필터, 색 묶기, 연결 요소, 흰 구분선으로 다시 나누기 |
| 구역 이름 | 도형마다 확대 타일을 만들어 Claude가 안에 쓰인 글자를 읽습니다(3번 투표). |
| 다듬기·자체 점검 | 범례 색 대조, 번호 계열의 빈 번호 찾기, 좌우대칭 맞추기, 이웃 구역 변 맞추기(`ZoneConsistency`, `ShapeRegularizer`) |

- **정확도**: 사람이 검수한 정답 지도로 측정합니다. 규칙 조정에 쓰지 않은 처음 보는 지도 35장(722구역)에서 IoU 0.8 이상이 **79.1%**, 정밀도 95.5%입니다. 조정에 쓴 5장에서는 96.1%입니다.
- **같은 지도는 다시 부르지 않음**: 사람이 검수한 지도와 좌석표가 같으면 AI 없이 검수 정답을 씁니다. 같은 링크의 결과는 168시간 보관합니다.
- **비용 관리**: 호출마다 토큰과 예상 비용을 기록합니다. 크레딧이 떨어지면 등록 화면이 직접 입력만으로 바뀝니다.
- **한계**: YES24는 봇 차단 때문에 상세 이미지를 읽지 못해 글자만 씁니다. 대신 사용자가 좌석표 이미지를 올릴 수 있습니다. 구역 하나가 등급 색으로 여러 조각인 돔 경기장 지도는 아직 약합니다.

> 옛 좌석 단위 인식(FastAPI·OpenCV·Tesseract)은 2026-10-07에 접었고, git 태그 `archive/seatmap-track-20261007`에만 남아 있습니다.

## 기술 스택

| 구분 | 기술 |
|---|---|
| Frontend | React, TypeScript, Vite, Tailwind CSS v4 |
| Backend | Spring Boot, Spring Security(JWT), JPA, WebSocket(STOMP), Flyway |
| DB | MySQL (Flyway V1~V26, 26개 테이블) |
| AI | Anthropic Claude Haiku 5.5(공식 Java SDK, structured outputs), 순수 Java 영상 처리 |
| 렌더러 | Debian Chromium `--headless=new` 컨테이너, CDP(격리 네트워크, 브라우저 위장 없음) |

## 설계에서 신경 쓴 것

- **동시성**: 잠금 순서를 티켓 id↑ → 요청 id↑ → 매칭으로 고정했습니다. 예약은 한 좌석에 한 사람만 성공합니다. 교환 완료는 한 트랜잭션에서 기존 티켓을 EXCHANGED로 바꾸고 새 티켓을 만듭니다.
- **외부 요청 안전**: 링크 읽기는 사이트와 숫자 ID만 뽑아 고정 템플릿으로 요청합니다. 공인 IP·https만 허용하고, 리다이렉트를 따르지 않으며, 크기·시간·횟수를 제한합니다. 로그인·캡차·봇 차단 우회와 내부 API 호출은 하지 않습니다.
- **개인정보**: AI 프롬프트에는 공개 공연 페이지의 글자·이미지만 넣습니다. 인증 사진은 처리가 끝나면 지우고, 좌석표 이미지는 저장하지 않습니다. 탈퇴하면 계정을 익명화합니다.
- **AI 결과는 보조 수단**: 자동 등록은 없고, 결과가 틀려도 등록은 막히지 않습니다. 서버가 AI 응답의 형식·범위를 항상 다시 검증합니다.

## 로컬에서 실행하기

```bash
cd MatJari
cp .env.example .env   # 값 채우기 (AI를 쓰려면 ANTHROPIC_API_KEY)
docker compose up --build
```

| 서비스 | 주소 |
|---|---|
| 프론트엔드 | http://localhost:5173 |
| 백엔드 API | http://localhost:8080/api |

키가 없으면 AI 없이 규칙 결과만 씁니다. 개별 실행, 테스트, 자동 배포는 [`MatJari/README.md`](./MatJari/README.md)를 참고하세요.

## AI로 개발한 방식

[Claude Code](https://claude.com/claude-code)의 서브에이전트·스킬(`.claude/agents`, `.claude/skills`)을 구성해 개발했습니다. 세션이 바뀌어도 설계 결정과 규칙이 유지되도록 했습니다.

- `backend-dev` / `frontend-dev`: 영역별 구현(worktree 격리)
- `db-schema-architect`: 스키마·마이그레이션 설계
- `code-reviewer`: 구현 뒤 리뷰
- `researcher` / `wiki-curator` / `Explore`: 조사, 위키 정리, 읽기 전용 탐색
- `doc-writer`: 산출물 문서 동기화
- `project-knowledge` 스킬: 현재 서비스 규칙과 구현 상태 요약
